## Interaction Contract

### Reorder Button Layout

Each list row in the ListEditor gains two new buttons **before** the existing Edit and Delete buttons. The row layout becomes:

```
[text label] [Move Up] [Move Down] [Edit] [Delete]
```

Row DOM order (left to right):
1. `<span>` item label (existing, `flex-1`)
2. Move Up button — `<Icon name="ChevronUp" size={14} />`
3. Move Down button — `<Icon name="ChevronDown" size={14} />`
4. Edit button — `<Icon name="Pencil" size={14} />` (existing)
5. Delete button — `<Icon name="Trash2" size={14} />` (existing)

### Button States

| State | Condition | Classes | Interaction |
|-------|-----------|---------|-------------|
| Enabled | Item can move in that direction | `bg-white/20 text-white/80 hover:bg-white/30 border border-white/30` | `onClick` swaps with adjacent item |
| Disabled (boundary) | Item is first (up) or last (down) | `bg-white/5 text-white/20 border-white/10 cursor-not-allowed` | No click handler fired |
| Disabled (Other) | `o === 'Other'` | `bg-white/5 text-white/20 border-white/10 cursor-not-allowed` | No click handler fired |
| Hover | Any enabled button | `hover:bg-white/30` | Smooth background transition |

### "Other" Pinned Behavior

- "Other" is always the last item in the array
- Both up and down buttons for "Other" are permanently disabled
- Uses the identical disabled class pattern as existing edit/delete: `bg-white/5 text-white/20 border-white/10 cursor-not-allowed`
- Tooltip: `"Cannot reorder Other"`

### Boundary Detection

- **First item**: Up button disabled (`i === 0`)
- **Last item** (before "Other"): Down button disabled only if the next item is "Other" (`items[i+1] === 'Other'`)
- "Other" itself: both buttons always disabled

### Reorder Mechanism

1. Click up arrow → swap `items[i]` with `items[i-1]` in the array
2. Click down arrow → swap `items[i]` with `items[i+1]` in the array
3. After swap, call existing `saveOptions(plat, approver, equip)` to persist to Firestore
4. Firestore `onSnapshot` listener in the existing `useEffect` re-renders all surfaces with new order
5. No new state variables needed — the existing `equipmentOptions`, `platOptions`, `approverOptions` state arrays are mutated in place via spread + filter (same pattern as `addOption`, `editOption`, `removeOption`)

### Reorder Function Pattern

Follow the existing mutation pattern (lines 240-260 of index.html):

```javascript
const moveOption = (list, fromIdx, toIdx) => {
    const next = { equipment: equipmentOptions, plat: platOptions, approver: approverOptions };
    const arr = [...next[list]];
    [arr[fromIdx], arr[toIdx]] = [arr[toIdx], arr[fromIdx]];
    next[list] = arr;
    saveOptions(next.plat, next.approver, next.equipment);
};
```

### Row Layout Changes

The existing ListEditor row div changes from:

```
<div className="flex items-center gap-2">
  <span> ... </span>
  <button>Edit</button>
  <button>Delete</button>
</div>
```

To:

```
<div className="flex items-center gap-2">
  <span> ... </span>
  <button>Move Up</button>
  <button>Move Down</button>
  <button>Edit</button>
  <button>Delete</button>
</div>
```

All buttons share the same sizing: `p-2 rounded-lg transition-all border`.

### Visual Legend Update

The Settings header legend (line 434-440) gains a new entry for reorder:

```
<div className="flex flex-col items-center gap-1">
  <span>Reorder</span>
  <div className="w-3 h-3 rounded-full bg-white/20 border border-white/40"></div>
</div>
```

This is inserted between the existing "Edit" and "Delete" legend items.
