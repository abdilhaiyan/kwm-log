## UI-SPEC Amendment Notes (user decisions Q1-Q4, signed-off 2026-09-16 — do NOT silently drop)

The approved UI-SPEC text is the locked visual/interaction contract. The four amendments below deviate from its literal text and are REQUIRED, each justified by a RESEARCH pitfall and live-data observation. They are recorded here so the deviation is explicit (quality gate: no silent drops, no silent acceptance).

1. **Q1 — Down-boundary amendment (RESEARCH Pitfall 2).** UI-SPEC Boundary Detection (lines 130-134) only disables Down when `items[i+1] === 'Other'`. Live Equipment data is `['DJI Osmo Action 6','Car','Other','Laptop']` — the last item is NOT `'Other'`, so the literal rule leaves Laptop's Down enabled and the swap writes `undefined` into the array, which saveOptions persists as `null`. Amendment: Down disabled when `o === 'Other' || i >= items.length - 1 || items[i+1] === 'Other'` (tooltip `Already at bottom` for the true-last case) AND `moveOption` guards `if (toIdx < 0 || toIdx >= arr.length) return;`.
2. **Q2 — addOption insert-before-Other (RESEARCH Pitfall 3).** Line 244 appends after `'Other'`, silently breaking the pin every time a manager adds an item — the live `'Laptop'` record is this bug in production. Amendment: when the last element is `'Other'`, insert the new value before it.
3. **Q3 — Legend placement.** UI-SPEC says the Reorder entry goes between Edit and Delete; row order is `[Up][Down][Edit][Delete]`, so the entry is inserted BEFORE Edit (line 435). Cosmetic only.
4. **Q4 — No load-time normalization.** The legacy `'Laptop'`-after-`'Other'` state is NOT auto-repaired on load (silent data mutation would surprise managers). It is repaired once via the manual Laptop up-move during UAT. Acceptance tests read LIVE doc data, never `DEFAULT_*` constants (RESEARCH A1).
